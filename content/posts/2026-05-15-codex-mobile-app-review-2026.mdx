## Codex 모바일 앱이란?

Codex는 OpenAI가 개발한 AI 코딩 에이전트다. 단순히 코드를 생성하는 것을 넘어, 파일 탐색·테스트 실행·버그 재현·PR 생성까지 실제 개발 작업을 자율적으로 처리한다.

기존에는 데스크톱 앱이나 CLI 환경에서만 사용할 수 있었다. 이번 업데이트로 [ChatGPT](https://chat.openai.com) 모바일 앱(iOS·Android)에서 Codex를 완전히 제어할 수 있게 됐다.

핵심 구조는 이렇다. Codex는 여전히 로컬 머신(노트북, Mac mini, 원격 서버 등)에서 실행된다. 스마트폰은 그 실행 상태를 실시간으로 받아보고, 지시를 내리고, 승인을 처리하는 컨트롤 패널 역할을 한다.

경쟁 도구와의 차이를 정리하면 아래와 같다.

| 구분 | Codex 모바일 | [GitHub Copilot](https://github.com/features/copilot) | [Cursor](https://cursor.com) |
|------|-------------|---------------|--------|
| 모바일 제어 | ✅ 완전 지원 | ❌ 미지원 | ❌ 미지원 |
| 에이전트 자율 실행 | ✅ 멀티 스텝 | 부분 | 부분 |
| Remote SSH 연결 | ✅ GA | ❌ | ✅ 제한적 |
| HIPAA 지원 | ✅ Enterprise | ❌ | ❌ |
| 무료 플랜 | ✅ | ✅ (제한) | ✅ (제한) |

[GitHub Copilot](https://github.com/features/copilot)은 IDE 내 자동완성이 강점이고, [Cursor](https://cursor.com)는 에디터 통합에 집중한다. Codex는 에이전트 자율성과 모바일 원격 제어라는 방향성에서 명확히 다른 길을 걷고 있다.

주간 활성 사용자가 400만 명을 넘었다는 점은 단순한 수치가 아니다. 이미 실무에서 Codex를 장시간 작업에 투입하는 팀이 상당하다는 의미다.


## 핵심 기능 5가지

### 1. 실시간 원격 제어 — 스마트폰이 콘솔이 된다

Codex 모바일 앱은 단순한 리모컨이 아니다. 연결된 머신의 라이브 상태를 앱으로 불러와 모든 스레드를 탐색할 수 있다.

실시간으로 수신되는 정보는 다음과 같다.

- **스크린샷:** 브라우저에서 재현 중인 버그 화면
- **터미널 출력:** 테스트 실행 결과, 빌드 로그
- **Diff:** 코드 변경 사항 리뷰
- **승인 요청:** Codex가 다음 단계 진행 전 사용자 확인이 필요할 때

이 모든 것이 단방향 알림이 아니라 양방향 인터랙션으로 처리된다. 스마트폰에서 승인 버튼을 누르면 로컬 머신의 Codex가 즉시 다음 단계를 실행한다.

보안 구조도 설계가 탄탄하다. 내부적으로는 보안 릴레이 레이어(Secure Relay Layer)를 사용해 머신을 공개 인터넷에 직접 노출하지 않는다. 자격증명, 파일, 권한 설정은 모두 실행 머신에 남아 있고, 앱에는 상태 업데이트만 흐른다.

### 2. Remote SSH — 원격 개발 환경 직접 연결

Remote SSH가 정식 출시(GA)됐다. 이는 팀 단위 개발자에게 특히 중요한 기능이다.

기존에는 Codex를 로컬 환경에서만 쓸 수 있었다. 이제는 SSH 설정 파일에서 호스트를 자동으로 감지해 원격 머신에 프로젝트를 만들고 스레드를 실행할 수 있다.

활용 흐름은 아래와 같다.

1. 데스크톱 앱에서 SSH 호스트 감지
2. 원격 머신에서 프로젝트 생성 및 Codex 실행
3. 동일한 보안 릴레이를 통해 모바일에서 접근
4. 스마트폰으로 실행 상태 확인 및 지시

기업 환경에서 승인된 의존성, 자격증명, 보안 정책, 컴퓨팅 자원이 모두 갖춰진 원격 서버에 바로 연결할 수 있다는 뜻이다.

### 3. Hooks — 프롬프트부터 동작까지 커스터마이징

Hooks 기능이 정식 출시(GA)됐다. Hooks는 Codex의 동작을 특정 저장소나 디렉터리 단위로 커스터마이징할 수 있는 확장 레이어다.

Hooks로 할 수 있는 것들:

| 활용 사례 | 설명 |
|----------|------|
| 시크릿 스캔 | 프롬프트에 민감한 정보가 포함되면 차단 |
| 검증기 실행 | 코드 변경 전후 자동 유효성 검사 |
| 대화 로깅 | 모든 Codex 대화 기록 저장 |
| 메모리 생성 | 반복 컨텍스트 자동 저장 |
| 저장소별 동작 커스터마이징 | 특정 레포에서만 다른 규칙 적용 |

Hooks는 단순 플러그인이 아니다. 조직의 보안 정책을 Codex 실행 흐름에 직접 심을 수 있는 수단이다. 특히 프롬프트 인젝션 위험을 줄이는 데도 활용할 수 있다.

### 4. 프로그래밍 방식 액세스 토큰 — CI/CD 통합

프로그래밍 방식 액세스 토큰(Programmatic Access Tokens)은 Enterprise·Business 플랜에서 사용할 수 있다.

[ChatGPT](https://chat.openai.com) 워크스페이스 설정에서 스코프가 지정된 자격증명을 직접 발급할 수 있다. 이를 이용하면:

- **CI 파이프라인**에서 Codex를 자동화 단계로 통합
- **릴리스 워크플로우**에 Codex 검토 단계 삽입
- **내부 자동화 도구**에서 Codex API 호출

사람이 직접 로그인하지 않아도 Codex를 워크플로우 안으로 끌어들일 수 있다는 것이 핵심이다.

### 5. HIPAA 지원 — 의료 조직의 실무 투입

[ChatGPT](https://chat.openai.com) Enterprise 워크스페이스를 사용하는 의료 기관은 이제 HIPAA 준수 환경에서 Codex를 사용할 수 있다.

적용 범위는 로컬 환경(CLI, IDE, 앱)이다. 환자 케어 지원 및 운영 워크플로우를 자동화하는 데 Codex를 활용할 수 있게 됐다.

단, 조건이 있다. HIPAA 지원은 Codex를 로컬 환경에서만 사용할 때만 적용된다. 원격 환경이나 클라우드 기반 실행에는 적용되지 않는다는 점을 반드시 확인해야 한다.


## 직접 써본 솔직한 후기

### 장점 1 — 이동 중에도 에이전트와 리듬이 끊기지 않는다

기존의 AI 코딩 도구는 데스크톱에 앉아 있을 때만 의미가 있었다. Codex 모바일은 이 전제를 바꾼다.

출근길 지하철에서 Codex가 막힌 지점에 방향을 잡아주고, 점심 시간에 떠오른 아이디어를 바로 스레드에 추가할 수 있다. 이런 짧은 개입이 쌓이면 하루 전체 작업 흐름이 달라진다.

특히 장시간 실행 작업에서 가치가 크다. Codex가 리팩터링을 처리하는 동안 사용자는 다른 일을 할 수 있고, 판단이 필요한 순간에만 스마트폰으로 응답하면 된다.

### 장점 2 — 보안 설계가 실용적이다

릴레이 레이어 구조는 단순히 보안을 강조하는 마케팅 문구가 아니다. 실제로 자격증명과 파일은 로컬 머신에 머물고, 앱에는 상태만 전달된다.

VPN 없이도 원격 머신에 안전하게 접근할 수 있다는 점은 팀 도입 장벽을 낮춘다. Remote SSH + 보안 릴레이 조합은 기업 환경에서 즉시 실용적으로 쓸 수 있는 구성이다.

### 장점 3 — 엔터프라이즈 기능이 한 번에 몰려왔다

이번 업데이트에서 Remote SSH GA, Hooks GA, 액세스 토큰, HIPAA 지원이 동시에 나왔다. 각각이 따로 있어도 가치 있는 기능들이다.

특히 Hooks + 액세스 토큰 조합은 Codex를 조직의 개발 파이프라인에 공식 단계로 편입시킬 수 있는 기반이 된다. 지금까지 Codex를 개인 도구로만 쓰던 팀이 조직 단위 도입을 검토할 수 있게 됐다.

### 아쉬운 점 1 — Windows 연결은 아직 지원 안 된다

모바일 앱에서 Codex 앱이 실행 중인 Windows PC에 연결하는 기능은 아직 출시되지 않았다. "곧 출시 예정(coming soon)"이라고만 나와 있다.

Windows를 주 개발 환경으로 사용하는 개발자라면 당장은 이 기능을 쓸 수 없다. macOS 환경이 먼저 지원된다는 점이 명확한 제약이다.

### 아쉬운 점 2 — 한국어 지원은 반쪽짜리다

[ChatGPT](https://chat.openai.com) 앱 자체 인터페이스는 한국어를 지원한다. 하지만 Codex의 실제 코딩 에이전트 응답과 터미널 출력은 영어 중심으로 돌아간다.

한국어로 지시를 내리면 어느 정도 이해하지만, 응답과 로그는 영어로 나오는 경우가 많다. 한국어 개발 문서나 주석이 포함된 코드베이스에서의 처리 품질은 영어 환경 대비 낮을 수 있다. 이 부분은 실사용 전에 직접 확인이 필요하다.

### 이런 분께 추천합니다

- **이동이 잦은 개발자:** 출퇴근, 출장 중에도 Codex 작업 흐름을 끊김 없이 유지하고 싶은 분
- **원격 개발 환경을 쓰는 팀:** SSH로 연결된 원격 서버에서 Codex를 직접 실행하고 싶은 DevOps 엔지니어
- **장시간 에이전트 작업이 많은 개발자:** 리팩터링, 버그 조사처럼 수십 분~수 시간 걸리는 작업을 에이전트에 맡기고 중간중간만 체크하고 싶은 분
- **CI/CD 자동화를 원하는 엔지니어링 팀(Enterprise):** Codex를 릴리스 파이프라인의 공식 단계로 편입하려는 팀
- **의료 분야 개발 팀:** HIPAA 준수 환경에서 AI 코딩 에이전트를 실무에 쓰고 싶은 헬스케어 조직

### 이런 분께는 비추천

- **Windows 주 사용자:** 현재 모바일 앱에서 Windows PC 연결이 지원되지 않는다. macOS 환경이 준비될 때까지 기다리는 게 낫다.
- **한국어 코드베이스 중심 팀:** 한국어 주석, 한국어 문서가 많은 프로젝트에서 Codex의 처리 품질이 영어 환경 대비 낮을 수 있다.
- **IDE 통합 자동완성이 주 목적인 분:** Codex는 에이전트 자율 실행에 강점이 있다. 타이핑 중 즉각적인 코드 자동완성을 원한다면 [GitHub Copilot](https://github.com/features/copilot)이 더 적합하다.
