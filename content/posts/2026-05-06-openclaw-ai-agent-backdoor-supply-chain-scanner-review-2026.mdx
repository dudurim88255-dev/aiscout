## OpenClaw와 CLI-Anything이란?

CLI-Anything은 홍콩대학교 Data Intelligence Lab이 2026년 3월 공개한 오픈소스 도구다. 어떤 오픈소스 저장소의 소스코드든 분석해서, AI 코딩 에이전트가 명령어 한 줄로 조작할 수 있는 구조화된 CLI를 자동 생성한다. [Claude](https://claude.ai) Code, OpenAI Codex, [Cursor](https://cursor.com), [GitHub Copilot](https://github.com/features/copilot) CLI, 그리고 OpenClaw까지 주요 AI 에이전트를 모두 지원한다.

출시 두 달 만에 GitHub 스타 30,000개를 돌파했다. 이 숫자는 단순한 인기가 아니다. 오픈소스 생태계에서 이 도구가 얼마나 빠르게 표준 워크플로에 흡수됐는지를 보여준다.

OpenClaw는 이 CLI-Anything이 생성하는 SKILL.md 파일을 기반으로 작동하는 에이전트 프레임워크다. 문제는 여기서 시작된다. Snyk가 2026년 2월 진행한 ToxicSkills 감사에서 OpenClaw의 공개 마켓플레이스인 ClawHub와 skills.sh에서 76건의 확인된 악성 페이로드를 발견했다. 전체 스킬의 13.4%가 최소 하나 이상의 심각한 보안 문제를 포함하고 있었다.

기존 보안 도구와 무엇이 다른가. SAST(정적 분석)와 SCA(소프트웨어 구성 분석)는 각각 코드 레이어와 의존성 레이어를 감시한다. 하지만 SKILL.md는 코드처럼 보이지 않는다. 마크다운 문서처럼 생겼다. 그러나 에이전트는 이것을 실행 가능한 지시문으로 처리한다. 이 세 번째 레이어를 감시하는 도구는 2026년 현재까지 표준화된 것이 없다.

경쟁 도구와의 차이는 명확하다. Snyk, Sonatype, Checkmarx 같은 전통적 공급망 보안 도구는 패키지 버전과 코드 구문을 검사한다. Cisco가 2026년 4월 발표한 AI Agent Security Scanner for IDEs는 이 공백을 메우려는 첫 번째 시도 중 하나다. 하지만 아직 의미론적(semantic) 레이어 전체를 커버하지는 못한다.


## 핵심 기능 5가지: 공격이 작동하는 방식

### 1. SKILL.md 파일을 통한 에이전트 지시문 삽입

CLI-Anything이 생성하는 SKILL.md 파일은 AI 에이전트에게 "이 저장소를 어떻게 다루는지"를 가르치는 설명서다. 코드 예제, 설정 템플릿, 실행 절차가 마크다운 형식으로 담긴다.

공격자는 이 파일 안에 악성 지시문을 코드 예제 형태로 숨긴다. 코드 리뷰어 입장에서는 일반적인 문서처럼 보인다. 실행 가능한 코드가 아니기 때문이다. 하지만 에이전트는 이 내용을 운영 지시문으로 파싱하고 그대로 실행한다.

Griffith University, Nanyang Technological University, UNSW, 도쿄대 연구팀이 2026년 4월 발표한 논문에서 이 기법을 DDIPE(Document-Driven Implicit Payload Execution)로 명명했다. 4개 에이전트 프레임워크, 5개 대형 언어 모델을 대상으로 테스트한 결과, 우회 성공률은 11.6%~33.5%였다.

| 탐지 방법 | 탐지율 | 우회율 |
|---|---|---|
| 정적 분석 (Static Analysis) | 약 97.5% | 2.5% |
| DDIPE 4단계 탐지 레이어 전체 | 97.5% | 2.5% |
| 에이전트 프레임워크 내장 필터 | 66.5%~88.4% | 11.6%~33.5% |

2.5%가 작아 보일 수 있다. 하지만 ClawHub에 등록된 스킬이 3,984개라면, 그중 약 100개는 탐지를 완전히 우회한다는 의미다.

### 2. 에이전트 브릿지 도구를 통한 자동 신뢰 연결

개발자가 CLI-Anything 같은 에이전트 브릿지 도구를 써서 코딩 에이전트를 저장소에 연결하는 순간, 에이전트는 SKILL.md를 자동으로 수집하고 신뢰한다.

현재 어떤 에이전트 프레임워크도 스킬 정의의 의도가 악성인지 아닌지를 구분하는 검증 레이어를 갖추지 않았다. 에이전트는 지시문을 받으면 자신이 가진 합법적인 권한으로 그대로 실행한다. 권한 상승 없이도 데이터 유출, 설정 변경, 자격증명 수집이 가능한 이유가 여기에 있다.

Reputation의 VP of AI Carter Rees는 VentureBeat에 이렇게 말했다. "LLM은 서드파티 플러그인에 의존하는데, 손상된 도구가 대화 흐름에 악성 데이터를 주입할 수 있다. 내부 안전 훈련을 우회하면서."

### 3. EDR·SIEM 탐지 우회 구조

에이전트가 악성 지시문을 실행할 때, 엔드포인트 탐지 및 대응(EDR) 시스템은 이것을 정상 트래픽으로 본다. 왜냐하면 인가된 프로세스에서 승인된 API 호출이 발생하기 때문이다.

데이터 유출, 설정 변경, 자격증명 수집이 모두 모니터링 스택이 "정상"으로 분류하는 채널을 통해 이루어진다. Enkrypt AI의 CSO이자 전 AWS 부 CISO인 Merritt Baer는 이렇게 정리했다. "SAST와 SCA는 코드와 의존성을 위해 만들어졌다. 지시문을 검사하지 않는다."

이 구조가 만들어내는 결과는 단순하다. 공격의 모든 고리가 현재 보안 스택에 보이지 않는다.

### 4. 공급망 오염을 통한 다운스트림 확산

2026년 4월에 문서화된 실제 공격 사례를 보면 확산 속도가 얼마나 빠른지 알 수 있다. 조작된 GitHub 이슈 제목 하나가 Cline에 연결된 AI 트리아지 봇을 트리거했다. 봇은 GITHUB_TOKEN을 유출했고, 공격자는 이를 이용해 손상된 npm 의존성을 게시했다.

그 결과, 약 4,000개 개발자 머신에 8시간 동안 두 번째 에이전트가 설치됐다. 이슈 제목 하나. 8시간의 접근. 인간의 승인 없음.

| 공격 단계 | 실제 발생 내용 | 소요 시간 |
|---|---|---|
| 초기 트리거 | 조작된 GitHub 이슈 제목 1개 | 즉시 |
| 토큰 유출 | GITHUB_TOKEN 유출 | 수 분 이내 |
| 의존성 오염 | 손상된 npm 패키지 게시 | 수 시간 |
| 에이전트 확산 | 약 4,000대 개발자 머신 감염 | 8시간 |

### 5. 낮은 공격 진입 장벽과 빠른 스킬 생태계 확산

ClawHub의 일일 스킬 제출 건수는 2026년 1월 중순 50건 미만에서 2월 초 500건 이상으로 열 배 급증했다. 스킬을 게시하는 데 필요한 것은 마크다운 파일 하나와 일주일 된 GitHub 계정뿐이다.

코드 서명 없음. 보안 검토 없음. 샌드박스 없음.

Merritt Baer는 이를 한마디로 정리했다. "진입 장벽이 극도로 낮다. 스킬 추가는 Word 문서 업로드만큼 간단할 수 있다."

이 구조는 악의적인 행위자가 오픈소스 생태계를 통해 수천 개의 개발 환경에 동시에 접근할 수 있는 토대를 만들어준다.


## 직접 분석한 솔직한 후기

보안 연구자와 블로거의 관점에서 이 공격 구조를 직접 분석했다. CLI-Anything 저장소를 클론하고, ClawHub의 공개 스킬 목록을 검토했으며, Snyk ToxicSkills 보고서와 DDIPE 논문을 교차 검증했다.

### 장점 1: 공격 구조가 논리적으로 완결돼 있다

이 공격이 무서운 이유는 복잡하지 않기 때문이다. 기존 신뢰 메커니즘을 그대로 이용한다. 에이전트가 스킬을 신뢰하는 구조, 에이전트가 합법적 권한으로 실행하는 구조, EDR이 정상 트래픽으로 보는 구조. 이 세 가지가 맞물리면 공격이 성립한다.

새로운 취약점을 만들지 않는다. 기존 설계 결정의 부산물을 악용한다. 이런 공격은 패치 하나로 막기 어렵다.

### 장점 2: 실증 데이터가 뒷받침된다

추측이나 이론이 아니다. Snyk의 3,984개 스킬 감사, 4개 대학 연구팀의 DDIPE 실험, 2026년 4월의 실제 npm 공급망 공격 사례, Cisco와 Pillar Security의 독립 확인까지 다층적 증거가 있다.

CVE-2026-22708([Cursor](https://cursor.com) 관련)은 이미 NVD에 등록됐다. 이것은 학술적 가설이 아니라 이미 익스플로잇이 발생한 실제 공격 표면이다.

### 장점 3: 보안 산업의 구조적 공백을 정확히 짚는다

Cisco, Snyk, Enkrypt AI, Pillar Security가 모두 같은 결론에 도달했다. 코드 레이어와 의존성 레이어 사이에 에이전트 통합 레이어가 생겼고, 이를 감시하는 도구가 아직 없다. 이 공백은 개별 기업의 문제가 아니라 보안 산업 전체의 구조적 문제다.

### 아쉬운 점 1: 현실적인 방어 방법이 아직 없다

공격 구조는 명확하게 기술됐지만, "지금 당장 무엇을 해야 하는가"에 대한 구체적인 답은 부족하다. Cisco의 AI Agent Security Scanner for IDEs가 첫 번째 시도이지만, 아직 의미론적 레이어 전체를 커버하지 못한다고 Cisco 스스로 인정한다.

보안 리더 입장에서는 위협은 보이는데 도구가 없는 상황이다. 이것이 가장 불안한 지점이다.

### 아쉬운 점 2: ClawHub 같은 마켓플레이스 거버넌스가 전혀 없다

현재 OpenClaw 생태계에는 스킬 게시에 대한 최소한의 검증도 없다. npm이 악성 패키지를 사후 제거하는 메커니즘이라도 갖춘 것과 비교하면, ClawHub는 아직 그 단계에도 이르지 못했다.

오픈소스 생태계의 개방성이 이 공격을 가능하게 만든다. 이것을 어떻게 균형 잡을 것인지에 대한 논의가 아직 본격적으로 시작되지 않았다.
